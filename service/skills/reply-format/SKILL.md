SUMMARY: 前端回复呈现：用轻量 Markdown 组织答复，并区分展示与真实执行。
# 前端回复格式

finishTurn.text 必须是非空的最终答复，同一 text 进入前端、上下文和压缩链路。先写清结果、依据和未完成项，再考虑排版。

## 前端实际渲染的范围

前端 `public/index.html` 自带一个轻量 Markdown 渲染器，逐行处理块级结构，且先把 HTML 转义再套标签，所以正文里的 HTML 标签、`onclick`、`javascript:` 只会当普通文字显示。支持：

- 段落（空行分段）；
- 无序列表（`-` / `*` / `+`）与有序列表（`1.` / `1)`）；
- 标题 `#`–`####`，降级渲染为 h3–h6；
- 围栏代码块 ```…```（等宽显示，不按语言高亮）；
- 行内代码 `` `x` ``、粗体 `**x**`、斜体 `*x*` 或 `_x_`。

不支持：表格、图片语法、链接语法 `[text](url)`、引用块、嵌套列表、HTML 标签。这些会按原文显示，所以不要把 URL 藏进 Markdown 链接，直接把完整 URL 写出来让用户复制。工具截图由前端单独渲染，不需要写进正文。

## 排版约定

- 结论先行：第一段写结果或答案，随后是依据、适用范围与未完成项。
- 列表层级不超过两层，不要用标题堆结构；一段表达一个意思。
- 改动与验证按「做了什么 / 怎么验证的 / 还差什么」的顺序写。
- 需要罗列成表的信息改用列表。
- 不重复工具名与内部字段，除非解释问题本身需要。

## 展示不等于执行

前端只负责显示文本。答复里写「已保存」「已提交」「已部署」不会触发任何动作；真实写入、对外发送、提交推送等必须由工具实际执行，并核对执行结果后，按已验证的事实描述。

## 检查实际结果

答复前核对交付内容：用户要求的每一项是否都有结果或明确说明缺口；声称完成的部分是否有执行证据。没有运行过的验证要写明未验证范围，不把代码写完当成行为已验证。
